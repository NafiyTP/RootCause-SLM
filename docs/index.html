RootCause-SLM

Anomaly detection on HDFS logs. A logistic regression on template counts finds the anomalous blocks (F1 0.973 on the full HDFS_v1 log, 11.2M lines). Then a fine-tuned Qwen2.5-1.5B tries to say why. Everything on this page runs in your browser: the detector is 55 weights.

playground · threshold · explanations · results · notes · code

playground

Paste raw HDFS lines, or load a real block from HDFS_v1. Then add or remove events with the − / + buttons and watch the score move.

threshold

The same detector on all 115,013 test blocks (the last 20% of the log, 1,679 anomalies). A block is flagged when its score is above the threshold.


explanations

123 test blocks (83 anomalous, 40 normal). Each system gets a summary of the block and must say whether something is wrong and what. The reference cause comes from fixed rules on the raw log.

rules = the pipeline's sentence · teacher = GPT-OSS 120B · v2 = Qwen2.5-1.5B + LoRA, trained on the teacher's answers. On normal blocks, "invented" means the system claimed a problem.

notes

Detection is the solid part. All false alarms at the default threshold are re-replication blocks: HDFS copying a block after losing a replica. The failure that caused it is logged on another machine, so from the block alone some look exactly like normal blocks.

The rule reference is silver, not gold: it cannot reward a correct cause the rules do not cover (for example naming the upstream IOException instead of "never stored"). A hand check of 30 anomalous blocks also showed a prompt flaw: the "normal block always has" list only shows events seen in at least 99% of normal blocks, so deletion (92%) looks abnormal to the model.
